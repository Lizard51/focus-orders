# Устройство приложения

«Фокус — Заказы» — офлайн-приложение Electron для одного пользователя Windows. Интерфейс написан на HTML/CSS/JavaScript; сервер и аккаунт для работы не нужны.

## Компоненты

| Файл | Ответственность |
|---|---|
| `src/main.cjs` | Единственное окно, одновременный запуск только одного экземпляра, IPC, нативные диалоги, буфер обмена и каталог данных |
| `src/preload.cjs` | Ограниченный `window.focusAPI` между интерфейсом и главным процессом |
| `src/store.cjs` | Схема базы, команды, версии, архив, шаблоны, импорт и резервные копии |
| `src/renderer.js` | Вкладки, черновики, автосохранение, подтверждения и состояния ошибки |
| `src/styles.css` | Светлый интерфейс «Фокус», адаптация окна и reduced motion |
| `src/seed.json` | Начальный редактируемый шаблон из 15 разделов; без заполненных заказов |

## Данные

В 1.1.0 добавлены необязательные поля schema1: `order.block` (цифры с ведущими нулями, `name` равен `Блок <block>`), `order/template.viewOrder` (перестановка четырёх видов), `section.view` (тип items разрешён также во fields). Старые записи без этих полей сохраняют имя, расположение и исходный порядок. Порядок разделов и строк задаётся массивами; порядок видов индивидуален для заказа/шаблона. Шаблон копируется в новый заказ, уже созданные независимы. Совместимость предусмотрена в направлении обновления; прежняя 1.0.1 не понимает дополнительные поля.

Номера вопросов вычисляются по непустым строкам type=q в порядке массива sections/items, не записываются в текст и не редактируются. Решённые вопросы сохраняют номер; кнопка копирования исключает решённые, оставляя показанные номера. Галочки view=fields не влияют на прогресс Проверки. Перетаскивание проверяет текущий draft, вид и область, запрещает смену родителя; перед действием сохраняет ожидающий ввод. Поиск затрагивает только видимый боковой список и не меняет базу/вкладки.

Обычная база — `%APPDATA%\FocusOrders\state.json`; последние 30 автоматических снимков — `backups` рядом. Установка и удаление программы не должны удалять этот каталог. Ручной экспорт содержит все заказы и шаблоны; восстановление заменяет всю базу после предпросмотра и подтверждения.

Команды выполняются последовательно. Для сохранения и удаления заказа передаётся `expectedVersion`; устаревшие изменения отклоняются. Запись идёт во временный файл с синхронизацией и переименованием; память изменяется после успешной записи. Перед заменой базы или удалением заказа создаётся дополнительный снимок. При повреждении/исчезновении основной базы используется последняя пригодная копия с предупреждением; если копии непригодны, пустая база поверх повреждённых данных не создаётся.

## Интерфейс и безопасность

Renderer не имеет доступа к Node.js: включены `contextIsolation`, `sandbox` и CSP. Главный процесс проверяет источник IPC и разрешённые команды. Внешние переходы и дополнительные окна запрещены. Текст пользователя экранируется. Длинные пункты раскрываются по высоте; ввод не заменяет поле на каждой букве. При ошибке сохранения черновик остаётся в окне для повторной попытки.

Это не облачная синхронизация: два компьютера не разделяют базу. Восстановление удалённого заказа через копию восстанавливает весь снимок базы, отдельной корзины нет.
